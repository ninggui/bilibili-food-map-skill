## 它解决什么问题

关注了几十个美食探店UP主，每个视频评论区置顶都有一长串店名清单。手动逐个搜百度地图、逐个收藏，一个城市就要花一下午，而且经常搜错城市、认错店名。

这个Skill把整个流程自动化：**B站API拉评论 → OCR识别店名 → 百度地图逐店验证 → 自动收藏 → 飞书文档归档**，一个视频从几小时压缩到几分钟。

## 为什么比手动强

| 手动操作 | 本Skill |
|---|---|
| 逐个打开视频翻评论找置顶 | B站API一键拉取全部视频置顶评论 |
| 凭记忆打字搜店名，经常打错字 | OCR提取+原文校准，形近字自动修正 |
| 搜到外省的店才发现城市错了 | 强制校验城市匹配，错了立刻标记 |
| 收藏成功与否全靠感觉 | 6项校验标准+成功率自动统计 |
| 店名存在哪？记在备忘录里 | 按博主→城市结构化写入飞书文档 |
| 一个城市一下午 | 一个城市10分钟 |

## 6项校验标准（每店必查）

每个店名必须通过全部6项才算收藏成功，否则标记❌并回查：

| # | 校验项 | 合格标准 | 不合格处理 |
|---|--------|----------|------------|
| 1 | **店名存在** | 百度地图搜索有精确匹配 | 搜不到→调整OCR形近字→仍搜不到→标记❌ |
| 2 | **城市匹配** | 地图左上角显示当前城市=视频主题城市 | 显示其他城市→标记❌，重新检查识别 |
| 3 | **类型正确** | 分类是美食/小吃/餐厅，不是酒店加油站 | 类型不对→标记❌，搜错了 |
| 4 | **评分正常** | 显示星级评分，一般≥3分 | 无评分→可能是小众店或名字错，重新核对 |
| 5 | **营业状态** | 正常显示，不是灰色/暂停营业 | 灰色/歇业→标记⚠️歇业中 |
| 6 | **地址合理** | 有详细地址（路名/小区/商圈） | 无地址→标记⚠️信息不全 |

## 质量门禁

交付前自动执行以下检查，不通过不交付：

- [ ] 每个城市店名数量和B站原文一致
- [ ] 标题里的"X家验证"和实际处理数量一致
- [ ] 单视频成功率≥90%
- [ ] 抽查每城市3-5家确认收藏成功
- [ ] 失败店名全部标记原因
- [ ] 视频链接已附在每个城市末尾

## 快速开始

- B站账号（需扫码登录，解除IP风控）
- 百度地图账号（需扫码登录网页版）
- 飞书文档权限

### 2. 基础配置

```python
# B站UP主空间链接
up_space_url = "https://space.bilibili.com/703057028/upload/video"

```

```
使用B站美食地图Skill。

```

## 遇到的坑 & 解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| B站API返回412/-352 | 直接curl被风控 | 浏览器登录态下用fetch调用 |
| OCR识别出错 | 手写体/艺术字形近字 | 回原文逐字核对，修正后重新搜索 |
| 店名搜到外省 | 没加城市前缀 | 搜索时强制加"城市+"前缀 |
| 只验证5家就标100% | 批量操作后没核对数量 | 数量一致性校验：标题数字必须=实际数量 |
| 收藏按钮没点到 | 批量操作坐标不准 | 每城市抽查3-5家确认 |
| 浏览器频繁超时 | 操作太频繁 | 每店间隔2-3秒，模拟人为操作 |

## 证据合同

| 等级 | 来源 | 写作规则 |
|------|------|----------|
| `verified` | 实际百度地图搜索结果+收藏成功 | 可以使用确定语气 |
| `user-provided` | 用户明确提供的UP主链接和要求 | 按原意写入 |
| `inferred` | 多项线索支持但未逐一验证 | 使用保守措辞 |
| `unknown` | 没有足够依据 | 省略，不编造 |

## 边界与限制

- 一次处理一个UP主，不批量跑多个UP主
- 置顶评论是图片版的需要额外OCR识别
- 百度地图官方没有批量收藏API，只能浏览器自动化逐个点
- 收藏操作频率要控制，避免被百度风控
- 不处理需要登录才能看的视频
