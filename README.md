## 它解决什么问题

关注了几十个美食探店UP主，每个视频评论区置顶都有一长串店名清单。手动逐个搜百度地图、逐个收藏，一个城市就要花一下午，而且经常搜错城市、认错店名。

这个Skill把整个流程自动化：**B站API拉评论 → OCR识别店名 → 百度地图逐店验证 → 自动收藏 → 飞书文档归档**，一个视频从几小时压缩到几分钟。

## 为什么比手动强

| 手动操作 | 本Skill |
|---|---|
| 逐个打开视频翻评论找置顶 | B站API一键拉取全部视频置顶评论 |
| 凭记忆打字搜店名，经常打错字 | OCR提取+原文校准，形近字自动修正 |
| 搜到外省的店才发现城市错了 | 强制校验城市匹配，错了立刻标记 |
| 收藏成功与否全靠感觉 | 6项校验标准+成功率自动统计 |
| 店名存在哪？记在备忘录里 | 按博主→城市结构化写入飞书文档 |
| 一个城市一下午 | 一个城市10分钟 |

## 7项校验标准（每店必查）

每个店名必须通过全部7项才算收藏成功，否则标记❌并回查：

| # | 校验项 | 合格标准 | 不合格处理 |
|---|--------|----------|------------|
| 1 | **店名存在** | 百度地图搜索有精确匹配 | 搜不到→调整OCR形近字→仍搜不到→标记❌ |
| 2 | **城市匹配** | 地图左上角显示当前城市=视频主题城市 | 显示其他城市→标记❌，重新检查识别 |
| 3 | **类型正确** | 分类是美食/小吃/餐厅，不是酒店加油站 | 类型不对→标记❌，搜错了 |
| 4 | **评分正常** | 显示星级评分，一般≥3分 | 无评分→可能是小众店或名字错，重新核对 |
| 5 | **营业状态** | 正常显示，不是灰色/暂停营业 | 灰色/歇业→标记⚠️歇业中 |
| 6 | **地址合理** | 有详细地址（路名/小区/商圈） | 无地址→标记⚠️信息不全 |
| 7 | **分店全收藏** | 同名所有分店全部收藏 | 只收藏了一家→回去把其他分店也收藏 |

## 断点续传机制

每个城市标题标记"应验证X家"，任务中断后从文档看进度：
- 应验证X家 - 已验证Y家 = 还差Z家
- 下次继续时，从第Y+1家开始，不用从头来
- 收藏完成后更新为：应验证X家：Y成功Z失败

## 质量门禁

交付前自动执行以下检查，不通过不交付：

- [ ] 每个城市店名数量和B站原文一致
- [ ] 标题里的"X家验证"和实际处理数量一致
- [ ] 单视频成功率≥90%
- [ ] 抽查每城市3-5家确认收藏成功
- [ ] 失败店名全部标记原因
- [ ] 视频链接已附在每个城市末尾

## 不同博主的店名位置（关键！）

不是每个博主都把店名放在评论区置顶，三种格式：

| 博主类型 | 店名位置 | 格式示例 | 提取方式 |
|-|-|-|-|
| 猴儿甜猴儿甜 | 评论区置顶 | 文字版直接列店名，或备忘录截图 | 文字直接读，图片OCR |
| 员外的觅食人生 | 视频简介 | "江岸区二七侧路：清真双宝红油牛系列" | 正则提取"地址：店名" |
| NAV看广州 | 视频标题 | "区域｜店名，描述..." | 正则按逗号切，取店名 |
| 柴西/赖导 | 评论区观众发的 | 旅行类，店名信息少 | 评论区翻找，效率低 |

## 百度收藏夹→高德迁移方案

百度地图没有批量导出API，但可以通过以下方式迁移：
1. 浏览器打开百度收藏夹分享链接，滚动加载全部地点
2. 解析DOM提取店名+地址，生成CSV（列：名称,地址，UTF-8-BOM）
3. 高德地图个人收藏夹不支持直接CSV导入
4. 走 wia.amap.com（高德数据管理）上传CSV批量导入
5. 注意：国庆等假期 wia.amap.com 会限制使用

## 速率限制与反爬经验（重要！）

### B站

| 操作 | 安全速率 | 被封风险 | 应对措施 |
|------|----------|----------|----------|
| 调API获取视频列表 | 每请求间隔3-5秒 | 高 | 必须浏览器登录态，不能直接curl |
| 调API获取评论 | 每请求间隔2-3秒 | 中 | wbi签名，否则-403 |
| 浏览用户空间页面 | 每页面间隔2秒 | 低 | 正常浏览器操作即可 |
| 批量获取视频简介 | 每视频间隔1.5-2秒 | 中 | 不要连续快速navigate |

**B站风控信号：**
- 返回412/-352/-799/-403 → IP被风控，需登录浏览器
- 视频列表返回空 → 触发限流，等5分钟再试
- 验证码弹出 → 必须人工处理，不能绕过

### 百度地图

| 操作 | 安全速率 | 被封风险 | 应对措施 |
|------|----------|----------|----------|
| 搜索店名 | 每店间隔2-3秒 | 低 | 加城市前缀搜索 |
| 点击收藏 | 每店间隔1-2秒 | 低 | 确认收藏成功后再搜下一家 |
| 切换城市 | 每城市间隔5秒 | 低 | 切换后等页面加载完 |

**百度地图注意事项：**
- 没有批量收藏API，只能浏览器自动化逐个收藏
- 浏览器频繁超时断开是正常的，重新连接即可
- 收藏按钮找不到 → 先截图看页面状态，不要盲目点击

### 小红书

| 操作 | 安全速率 | 被封风险 | 应对措施 |
|------|----------|----------|----------|
| 搜索关键词 | 每次搜索间隔5秒 | 中 | 不要连续搜索 |
| 浏览笔记列表 | 每页间隔3秒 | 低 | 正常滚动即可 |
| 打开笔记详情 | 每篇间隔5秒 | 高 | 频繁打开会触发验证码 |
| 下载图片 | 每张间隔3秒 | 中 | 直接curl下载带签名的URL |

**小红书风控信号：**
- 笔记列表加载不出来 → 触发反爬，等10分钟
- 验证码弹出 → 必须人工处理
- 图片加载失败 → 换个时间段再试

### 通用原则

1. **模拟人为操作**：不要像机器一样连续快速操作，要有停顿
2. **遇到超时不要慌**：等5秒重新连接，不要反复刷新
3. **被风控后不要继续**：停下来等10-30分钟，否则账号会被封
4. **记录断点**：每处理完一个城市就更新飞书文档，中断后可续传
5. **每天控制总量**：每天处理不超过50家店，避免账号被标记

## 遇到的坑 & 解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| B站API返回412/-352 | 直接curl被风控 | 浏览器登录态下用fetch调用 |
| OCR识别出错 | 手写体/艺术字形近字 | 回原文逐字核对，修正后重新搜索 |
| 店名搜到外省 | 没加城市前缀 | 搜索时强制加"城市+"前缀 |
| 只验证5家就标100% | 批量操作后没核对数量 | 数量一致性校验：标题数字必须=实际数量 |
| 收藏按钮没点到 | 批量操作坐标不准 | 每城市抽查3-5家确认 |
| 浏览器频繁超时 | 操作太频繁 | 每店间隔2-3秒，模拟人为操作 |
| B站API分页返回重复数据 | 分页bug | 546条记录去重后只有42个不同视频，风控解除后需重新拉 |
| 虚拟环境WebGL software only | 无GPU | 高德地图POI面板不渲染，改用general_search搜索POI数据替代 |
| 每3-5家就弹滑块验证码 | 百度风控 | 模拟人为操作节奏（5-15秒随机间隔），不要太规律 |
| OCR把"么"识别成"幺" | 形近字 | 回原图重新辨认，修正后重新搜索 |
| 顺德"大良/杏坛/勒流"被当成店名 | 提取正则bug | 格式是"城市｜片区，店名"，店名在第二个逗号后面 |
| 店名跨多个城市 | 广州/佛山/顺德混在一起 | 店名前加城市前缀（广州·/佛山·/顺德·），防止搜索混淆 |

## 边界与限制

- 一次处理一个UP主，不批量跑多个UP主
- 置顶评论是图片版的需要额外OCR识别
- 百度地图官方没有批量收藏API，只能浏览器自动化逐个点
- 收藏操作频率要控制，避免被百度风控
- 不处理需要登录才能看的视频
